## 规格列出的遗留（本计划不做）
- 多月折扣价 / 机组差异化定价 / 优惠券。
- 预订改期（取消后重订）；候补 / 排队；预订开通成功短信；邮件 / 站内信。
- 后台代用户下单、后台替用户开关自动续费。
- 取消手续费与预订上限的后台可配置（常量）。
- 指定机器的「硬保证」；跨商品机组限制。
- 即时订单开通失败自动换机（仍是失败 + 退款）。
- 把 `rack / slot / lan_ip / PDU` 的修改开放到后台。
- 机器日历的 ICS 导出；控制台按机组的历史出租率。
- 机器离线时预订的提前预警（只有开通时刻才改派）；更智能的装箱（best-fit 单次贪心）。
- 自动续费的数量 > 1、升档。

## 可以继续延后

### 与规格的界面差异（预检 D25 裁定：先用简化界面）
- 即时分支的 `no_capacity` 保持旧消息与错误值（前端引导依赖），只有预订分支带台数。
- 控制台实例列表的「批次折叠」实现为批次列 / 标签 + `?batch=` 筛选视图，不做视觉折叠（未筛选的列表不折叠也已裁定接受）。
- 后台机器详情的「档期」只有列表，没有规格 §12 的 60 天横向时间轴；机组「管理机器」抽屉用机器 ID 输入加「未分组机器」候选列表（按机柜筛选、分页）代替勾选表；改派对话框用机器 ID 输入代替下拉。

### 后端
- 候选机器改为 best-fit 排序后，`placeOrder` / `runningInstance` 拿到哪台空闲机器不再严格按 id：现有 e2e 里按 `ids[0]` 操作的用例在 Task 21 的全量 `make e2e` 中复核过。
- 后台取消预订也发短信（规格表只写了平台无法履约 / 失去资格两种；取消原因不进短信，短信里统一写「平台取消」）。
- 机器日历匿名可见会暴露单机占用情况（设计已接受）。
- 实例视图每台实例查两次（展示名 / 机组名有请求内缓存，`renewable_until` 每台一次）；列表上限 100 条可接受。
- `UserEvents` 读取最近 200 条事件再按白名单过滤出前 20 条；白名单外的事件极多时可能不足 20 条，事件量大的实例可改为 SQL 侧过滤。
- 并发下单时的假 `no_capacity`：挑机器遇到被别的事务锁住的行时会退避重挑（最多 3 次、每次 20～80ms，`9328b2e`），但锁持有超过约 240ms（数据库或连接池极端繁忙）时理论上仍会报「暂无可用机器」。所有运行（含 `-race`）都没出现过（Task 16、修复评审）。
- `instances.updated_at` 的语义变了：`RefreshCappedLeases` 用它做轮转游标，每轮把处理过的停机 / 洗机 / 暂停实例推到 `now`，所以它不再表示「最近一次业务变更」。以后要按「最近变更」排序或筛选的功能不能依赖它（Task 2 评审；规格 §4.3 已注明）。
- `refreshLease` 并发撞排他约束时在保存点里重试一次，再撞才返回 `ErrNoCapacity`：只在「刚读完封顶值、另一个事务又在同一台机器上插入更早的预订」时出现，暂停 / 停机实例的那一轮清扫会报错并在下一轮重试（Task 2 评审；规格 §4.3 已同步）。
- `RenewQuantity` 并发同键时的兜底（`isIdempotencyViolation`）只重读订单、不重读批次；批次检查在咨询锁内完成，实际走不到（Task 5）。
- 预订实例在开始前被暂停（机器失联）时，`addTime` 暂停分支按「暂停剩余 + 加时」计算到期提醒标记，会低估到期前的时间；只影响提醒标记，恢复时会重新计算（Task 11）。
- 立即结束的实例在 `DailyOccupancy`（仪表盘出租率）里多算 1 秒：时段至少 1 秒是 `machine_leases_period_nonempty` 的直接结果（Task 1）。
- `fleet.IdleCount` 在 api 层已无调用方（市场页改为即时可租台数），暂时保留（Task 12）。
- 改派后旧机器上的孤儿容器清理要等该实例在新机器上没有未完成的 Create 指令后，由下一次 StateReport 触发（`enqueueIfIdle` 按实例 ID 去重；现有行为，`TestBookingReassignChainHTTP` 固定了它）（Task 16）。
- 机器展示名的校验：拒绝控制字符与 Cf 类字符、拒绝形如 `机器 #<数字>` 的名字；全角数字、不换行空格（NBSP）、U+2028 等变体没有专门处理（Task 3 评审，已搁置）。
- 后台：`invalid_totp` 的文案仍是「动态码错误或已使用过」（恢复码重复使用也走这条）；命令行首次绑定只对 `invalid_totp` 重试，新绑定不会遇到 `totp_used`（`07fc330`）。

## 实施中确定的产品行为（裁定）

### 负责人授权的裁定（规格 §1.3）
- B1 预订参数：最早 2 小时后开始、最多提前 60 天、单次 ≤ 90 天、一单 ≤ 8 台、每用户未开通预订 ≤ 16 台；开始时刻取北京时间整点。
- B2 允许指定机器，但只承诺机组：机器故障 / 被占时在同机组内改派并在控制台与事件里注明；「不限机组」的预订可改派到任意可见机组。
- B3 租期沿用三档 × 数量，不加多月折扣价；长期租约 = `1m×N` + 自动续费。
- B4 取消退款：下单后 15 分钟内（冷静期）全退；此后距开始 ≥ 24h 全退、< 24h 退 50%；开通（开始前 1h）后不可取消；平台原因全退。
- B5 自动续费在到期前 1h 扣款，余额不足重试到到期，被预订挡住时自动降档。
- B6 预订付款即全额扣款，不做冻结。
- B7 后台取消预订需要 ops + 动态码（会退款）；改派只需 ops；机组管理 ops。
- B8 机器对外展示名 `display_name` 由后台设置（空时控制台显示 `机器 #<id>`），序列号与内网 IP 不对用户展示。
- B9 未分组机器只参与「不限机组」分配、不出现在机组列表；机组可设「仅后台可见」（`visible=false`）。
- B10 即时订单也用「租期 × 数量」并受 90 天上限约束；`POST /orders` 保留，等价于 `count=1, quantity=1, 立即开始`。
- B11 预订开通成功不发短信；自动续费失败与平台取消预订发短信。
- B12 机器进入维护时若有未开通的预订，后台提示数量与最早开始时间，但允许进入；预订在开通时自动改派。

### 执行中的裁定
- `fleet.Allocate` 删除，候选选择全部在 `rental.pickMachines`；`fleet.MarkAllocated` 只做状态切换。
- `POST /orders` 不建批次、键原样写在订单上；`POST /bookings` 建批次、子单键 `<key>#<n>`；用户键禁止含 `#`。幂等键按「意图」使用，重放时不看请求体（README「API 约定」）。
- 自动续费降档只在被预订挡住时发生，订单与事件记实际档位。
- 迟开通被下一预订封顶的差额按最新订单单价自动退款（remark「迟开通补偿」）。
- 自动续费失败标记写在该行事务里（savepoint 回滚扣款尝试），不是独立连接的事务；效果等价（Task 10）。「首次失败」指上次清除标记以来的第一次：失败原因从余额不足变为被预订挡住时不再发第二条短信；手动续费、后台延长、自动续费成功都会清除标记，之后再失败按首次失败重发短信。加时路径内部报出的 `renew_blocked` 也按自动续费失败处理（记标记、首次发短信），不按行错误每分钟重试。
- 后台换机（`AdminMigrate`）新实例的 `group_id` 取**新机器**的机组（不是原实例的）：展示名与机组保持一致，删除机组的检查也以实际机器为准；代价是换机后用户看到的机组可能变化（后台操作，可接受）。规格 §8 已同步（Task 4 评审）。
- 后台改派到指定机器时，实例 `group_id` 改为目标机器的机组（与换机一致），之后的自动改派与展示都以新机组为准；指定的目标机器用 `FOR NO KEY UPDATE` 等待加锁而不是跳过（`72ce47c`）。规格 §10.2、§14 已同步（Task 13 评审）。
- 所有机器行锁一律 `FOR NO KEY UPDATE`（`FOR UPDATE` 会与插入引用 `machines(id)` 的行所取的 `FOR KEY SHARE` 互斥），心跳也一样；删除机组时对机组行用 `FOR UPDATE`（该行要删除，必须与外键锁冲突）（计划评审 M1、Task 3、Task 6）。规格 §4.2、§5.2、§14 已同步。
- `refreshLease` 的封顶 UPDATE 在保存点里执行，并发撞排他约束时重试一次，再撞返回 `ErrNoCapacity`（规格原文是「不再可能撞约束、删除 `ErrNoCapacity` 分支」）。规格 §4.3 已同步（Task 2 评审）。
- 并发下单时挑机器遇到被锁的空闲机器（`SKIP LOCKED` 跳过）且台数不足时，退避 20～80ms 后重挑，最多 3 次，避免假的 `no_capacity`；代价是争用时延迟略增（`9328b2e`，规格 §4.2 已同步）。
- 机器日历的 `busy_until` 取「最近一条当前或未来时段」的上界，不取所有时段的最大值（规格 §10.1，Task 11 评审）。
- 机器恢复在线（`ResumeMachine`）时，若到期时间被下一条预订封顶（失联属于平台原因），被截掉的时长按 `quote` / `refundAcross` 退款并写事件，与迟开通补偿同一做法（Task 12 评审）。预订实例在开始前的暂停 / 恢复不缩短已付时长（`expires = max(now, S) + 暂停时剩余`，Task 8 评审）。
- 后台延长（`AdminExtend`）也允许 `reserved` 实例（后台界面对预订显示延长），同样先过 `renewFits`（Task 20 评审）。
- 后台二次验证（step-up）窗口只在操作成功后才打开：参数错误、业务失败都不会让后续操作免输动态码（`b5fa311`，Task 16 评审）。
- 重复提交一个已用过的正确动态码返回 `totp_used`（「该动态码已使用，请等待下一个动态码」），不计入失败次数与锁定；控制台 / 后台请求层对此重新弹框并提示，不计入 3 次输错上限（`07fc330`）。
- 机组「管理机器」、机器详情档期、批次折叠等界面按计划的简化版实现（预检 D25，见「与规格的界面差异」）；预检 D1～D27 的其余建议全部按扫描结果采纳（D24 另加迁移往返、可用台数性质、改派死锁重试、应用级改派链四组测试）。
- 计划评审 M3（把测试机 sudo 密码存进钥匙串）不采纳：负责人不允许持久化 sudo 密码，只在运行时用环境变量传入。
